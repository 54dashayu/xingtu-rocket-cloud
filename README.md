<h1 align="center">星途 · 火箭云预测</h1>
<p align="center">全球航天发射日历与火箭云观测条件推演 · V0.01</p>
<p align="center"><a href="https://space.bh1jss.net/launch/rocket-cloud/">在线使用</a> · <a href="docs/MODEL.md">设计思路与数学模型</a> · <a href="docs/DATA.md">数据与接口</a> · <a href="docs/ROADMAP.md">改进路线</a></p>

最近，长征六号甲等火箭发射后的“火箭云”“太空水母”视频让我产生了一个想法：既然我已经做了[星途·全球航天发射日历](https://space.bh1jss.net/launch/)，为什么不进一步结合发射参数、晨昏光照和天气，估算下一次有没有机会看到火箭云？

我希望用一个页面回答：**哪次发射值得关注、什么时候看、哪些区域可能具备观看条件？** 工具从任务时间和场址出发，在每个模拟时刻计算尾迹是否受光、地面观察者的太阳高度和视线仰角，再为候选观测点查询天气。新闻影像作为独立观测证据，显示在任务卡片的“已证实火箭云”标记中。

我把它作为一个公开、可复现的**观测条件推演工具**持续完善。目前尚未完成可见概率的统计验证，参考轨迹不等于任务遥测，地图蓝色范围也不代表必然可见。[notam-whisper](https://github.com/lzq1206/notam-whisper) 等公开项目已经先行探索相关方向，我希望在这些探索之外，分享自己的实现思路与实践。

## V0.01 已实现

- 全球发射场地图，未来／回溯 30 天任务，按任务数量缩放场址标记。
- 当地时间与北京时间、任务时刻的动态晨昏线；同属北京时间区不重复显示。
- 上升段动力学参考模拟，100／150 km 分析截点，T0 标记与多档播放速度。
- 当前时刻的动态观看区域；受光尾迹留存、低仰角边缘和“水母云关注区”分层。
- 发射参数 → 几何条件 → 天气采样的评估流程；手动填写当地时间后更新推演。
- NOTAM／MSI 候选方位区间，可选择用于未来任务的模拟航向约束。**仅时空与场址几何匹配，未自动确认任务对应关系。**历史航向不由实时通告反推。
- 日历订阅、PNG／SVG 独立标志、电脑与窄屏布局。

没有 KML 导出功能。

## 本地运行

Node.js 20 或更高版本；运行时无 npm 第三方依赖。

```sh
git clone https://github.com/54dashayu/xingtu-rocket-cloud.git
cd xingtu-rocket-cloud
npm start
# http://127.0.0.1:4173/
```

首次运行会请求 Launch Library 2，网络或上游限流时页面会提示数据状态。仓库不附带生产缓存，不能离线获得最新发射计划。

```sh
npm run verify
node scripts/validate-cloud-cases.mjs
```

测试覆盖太阳几何、坐标／时区、上升积分、尾迹时间、航警区间、天气缺测及日历接口。离线历史案例脚本用于检查时间和模型边界，**不提供命中率结论**。测试夹具不是线上任务数据。

## 如何阅读结果

| 显示 | 含义 |
|---|---|
| 预测／上升轨迹参考演示 | 缺少任务采样轨迹时，由通用参考参数积分得到 |
| 可能观看区 | 当前时间下受光、地面明暗、仰角满足几何阈值 |
| 水母云关注区 | 分级参考高度以上的一类几何区域，不是云形态计算结果 |
| 天气遮挡较少 | 有限采样点的云量、降水和可用能见度满足经验规则 |
| 已证实火箭云 | 收录了关联任务的观测报道，不是模型计算出的“事实” |
| 航警模拟约束 | 用户选择指向通告区域的方位范围，不等于真实起飞航向 |

## 目录

`public/map/` 包含地图、太阳位置、轨迹与可见几何；`src/` 提供发射缓存、天气与航警接口；`data/` 保存有来源的补充记录与结构定义；`test/` 是离线自动测试。

此公开版本专注 Web 工具，不包含原发射日历的微信小程序及生产部署备份。`public/index.html` 与 `public/map.html` 都打开火箭云界面。
