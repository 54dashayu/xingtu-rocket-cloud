# 部署说明

此目录提供部署和后台巡检样例，不包含生产主机凭据。请按自己的域名、路径、用户、端口和运行时调整。

- 运行Node服务前配置环境变量，参考根目录 `.env.example`。
- 日历和火箭云若分别部署，应让两者共用 `LAUNCH_SNAPSHOT_FILE`；仅一个服务写入，第二个设置 `LAUNCH_FEED_READ_ONLY=true`。
- 公网参考入口为 `/launch/` 和 `/rocket-cloud/`。仓库本地默认首页是独立日历，地图为 `map.html`；部署整合页时将其映射到对应目录首页，并校对资源/API相对路径。
- 不要将运行缓存放在每次替换的静态发布目录中。切换发布目录前备份并验证，保留上一个目录用于回退。
- `xingtu-launch-watchdog.*` 与 `launch-watchdog.py` 是后台巡检样例。0036客户端停止周期刷新不影响后台采集和巡检。
- `analytics/` 为可选统计/报告审核服务，管理页面需要独立认证和受限访问。部署者应配置自己的密钥和数据保留策略。

历史发布文档仅记录当时状态，不作为当前主机操作指令；此公开仓库不附带生产部署备份或内部协调记录。
