# 路线与同类项目观察

## 先解决数据约束，再谈准确率

1. 航警候选方向接口已接入；下一步需要任务关联、通告变更／撤销、分日时段与历史归档，确认区域用途后才能提高约束等级。
2. 补充有出处的分级、点火、关车和位置采样；不同火箭采用独立参数与不确定性范围，不能让通用参考模型承担真实遥测的角色。
3. 观测区域采用更细网格和自适应边界，比较不同轨迹／航向的集合范围，而不是给出虚假的单一精确边界。
4. 尾迹扩散、亮度衰减和高层风场；先明确物理假设与可获得参数，再决定能否从“几何条件”推进到“可见性概率”。
5. 观测窗口全程天气、多点云层与视线遮挡；并用包含失败观测的独立样本评价。

没有计划加入 KML 导出。

## notam-whisper 的价值与边界

2026-10-24 核查的 [公开仓库](https://github.com/lzq1206/notam-whisper) 提供通告采集、坐标转换、时段过滤、地图和历史归档，适合寻找发射相关空域／海域线索。[作者 2026-03-25 的更新记录](https://www.sina.cn/news/detail/5280368546808326.html) 已介绍其火箭云提示功能，因此本项目不以“首创”“最早”宣传。

所检查网页的 `isRocketCloudVisible` 以通告有效时段中点及区域位置的晨昏时段作发光提示，对较长窗口有限制。这种机制适合摄影候选筛选，但不是逐高度尾迹受光、观察者仰角与天气联合求得的可见范围；不能把发光区域当成必然能看到火箭云。

我们的侧重点是时间连续的参考上升与受光尾迹、观察者几何和天气采样；目前同样缺少充分的真实轨迹和独立精度验证。二者适合互补，不能只凭功能数断言谁更准确。NOTAM 接口使用其聚合数据并明确来源，没有复用其 GPL 程序代码；后续若复用代码需单独处理许可兼容。
