# v0.03 build 0019 — 导航、任务档案与发射数据同步

手机上的地图、日历、观测分析、火箭云 3D、报告/档案均保留底部导航。3D 跨页切换保留当前任务。档案列表以可展开的任务卡片展示，点击后才加载照片和来源；回放模拟与 3D 按钮使用一致的尺寸和样式。用户照片按任务关联查询，仍须公开同意和审核通过，保留署名。

## 发射数据更新

两套服务使用同一份原子写入的快照，火箭云服务是唯一上游写入者，日历服务只读。快照保留任务 ID、上游更新时间及原始结果状态；发射计划转入历史列表时按 ID 合并，不把已经过计划时间自动当成发射成功。

- 后续分页失败仍保留先前成功取得的任务，同时保留旧记录；不会把部分更新标成完整刷新。
- 每分钟检查更新需要。通常 30 分钟刷新，发射时刻前后 2 小时缩短到 5 分钟；前台每分钟重新读取快照。
- 失败自动退避重试，HTTP 429 遵守 Retry-After，共享冷却状态并跨进程重启保留。
- 任务从 upcoming 暂时消失、previous 又暂时不可用时，保留原任务并显示结果待更新。
- 快照暂时无法读取时保留已有副本；冷启动且没有可读副本则返回错误，不发送空列表覆盖用户缓存。
- 网页后台刷新不打断当前地图回放或清空用户正在填写的报告。

上游长时间故障仍会延迟新任务与结果；这套恢复机制不能创造上游尚未提供的数据。

## 部署

`LAUNCH_SNAPSHOT_FILE` 指向共享文件，唯一写入服务使用 `LAUNCH_FEED_READ_ONLY=false`，第二服务使用 `true`。首次迁移合并两边已有缓存和日历归档，保留上游时间。现有 ICS 订阅归档独立保留。运行缓存不入仓库。
