# v0.03 build 0025 — 航警疑似发射补漏

发射日历与火箭云继续共用同一份服务端快照。LL2 未收录的短时航警组合也可以生成“待核实任务”，不需要先有正式任务才能发现线索。

## 数据与判定

- 来源是现有 NOTAM 公开聚合 `https://rocket.rainywhisper.com/notams.csv`，非官方接口。本次没有接入或宣称已接入国内官方发射日程 API。
- 每 30 分钟检查一次，与 LL2 的请求预算、429 退避独立。源失败时保留尚未过期的候选并自动重试；接口返回 `meta.warningDiscovery`，包含检查时间、成功时间和状态。
- 首版仅识别中国通告：未来 30 天、单条不超过 2 小时、至少两个时间相近且重叠的危险区，通告之间相距至少 150 km，指向同一已知发射场。中心方位差不超过 5°，存在近似同分场址时不自动归属。排除训练、回收、取消、宽时间窗等。以上是筛选启发式，不是官方发射确认。
- 候选 ID 由场址和通告编号生成，重复刷新不重复添加。正式任务的精确时刻处于窗口前后 30 分钟内且同一场址时，只有唯一匹配才合并为正式任务；航警保留为参考资料，不覆盖正式任务身份、时刻、航向。
- 时间窗在两边网页明确标注为“非点火时间”。不作发射倒计时，不导出精确 ICS 事件。手动输入模拟时间仍可运行情景演示；通告中心方向仅标为估算，不能当作真实轨迹。
- 通告撤销、从成功刷新的源中消失或时间窗过期时移除候选，不凭航警把它变成“发射成功”的历史任务。

## 本次实例

A5897/26 与 A5898/26 自动产生“太原疑似发射（待核实）”，合并通告时间窗为北京时间 2026-11-19 06:43—07:10。任务名称、火箭型号和精确点火时刻仍未知。未把截图中的 186.9° 当作真实航向，也未把其他二手日程中的任务名称当成已确认事实。

## 验证与发布

- 单元测试覆盖真实通告样本、歧义场址、取消/过期、LL2 429 时独立发现、源失败保留、正式任务合并、只读服务同步、手动模拟时刻和 ICS 排除。
- 公网两边均返回 revision 406、21 条近期任务，含同一候选 ID；两个单任务 ICS 接口均拒绝导出未核实精确时间。
- 网页使用固定入口 `/launch/`、`/rocket-cloud/`；无需安装新的原生包获取服务端新任务。旧原生客户端对新增状态的具体排版未在本次真机验收。
- 日历有独立的部署前端，保留原有功能，仅补充时间窗显示。对应差异保存在 `deploy/calendar-notice-window.patch`。火箭云部署保留既有地图配置接口和 HTML 缓存策略。
- 上一发布：火箭云 `v0.03-0024-20261111`，日历 `feed-0023-20261111`。新版为 `v0.03-0025-20261111` 与 `feed-0025-20261111`。切换失败可恢复旧目录并重启服务；快照备份位于服务器 `/var/backups/xingtu-0025-20261111/`。

这能减少一类漏项，不能保证识别所有发射。没有公开通告、只有一个危险区、源本身遗漏或不满足几何筛选的任务仍需官方公告等补充。
